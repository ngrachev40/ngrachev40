# Job Search Agent — Project Case Study

## О проекте

Job Search Agent — Telegram-бот для поиска и отбора вакансий под профиль пользователя. Проект развивается как pet-project и одновременно как практический QA/engineering кейс.

Главная задача системы — не просто собрать вакансии, а отфильтровать их по профилю пользователя и не перегружать поиск дорогими AI-вызовами.

## Основные возможности

- Telegram onboarding и профиль пользователя
- выбор рынка вакансий и языка
- двухуровневая taxonomy профессий
- несколько источников вакансий
- единая база вакансий
- scheduled ingestion
- deduplication
- title-first matcher
- grading результатов
- per-user history
- Save / Applied / Skip
- AI fallback только для неоднозначных случаев

## Архитектура

Высокоуровневая цепочка:

Sources → Scheduled Collectors → Vacancy Database → Normalization → Deduplication → User Search → Matcher → Result Grading → Telegram UI

Пользовательский поиск не должен напрямую запускать сбор вакансий из внешних источников. Это уменьшает latency и делает поведение предсказуемее.

## QA-задачи в проекте

В рамках проекта выполнялись:

- проверка требований и продуктовой логики;
- smoke testing после изменений;
- regression testing matcher и history logic;
- проверки multi-user поведения;
- проверки source pool / cache;
- проверки ошибок внешних API;
- тестирование fallback-логики;
- тестирование Telegram callbacks;
- проверка сохранения пользовательского профиля;
- проверка выдачи вакансий и исключения повторов;
- тестирование server deployment;
- анализ production-like логов и дефектов.

## Найденные и исправленные проблемы

Примеры реальных дефектов/рисков, выявленных во время разработки:

- ложная классификация QA из-за совпадения коротких подстрок;
- нерелевантные вакансии из-за слишком широкого анализа description;
- некорректные/слишком общие salary-значения отдельных источников;
- ситуация, когда deep results существовали, но safety/fallback оставлял нулевую выдачу;
- несовместимость старой версии google-genai с используемым API;
- слабая выдача для российского профиля из-за международной базы источников;
- уменьшение top-6 после Applied/Skip без добора следующих вакансий;
- необходимость отделить ingestion от пользовательского search flow.

## Текущий статус

Проект находится в активной разработке. v4 включает SQLite vacancy database, scheduled collectors, matcher v5, taxonomy и Telegram whitelist.

Production-ready статус подтверждается только после live smoke внешних источников и Telegram flow.
